# HoloSolve スコア計算モデル技術資料

ホロライブドリームスのユニットスコア計算式を、ゲーム内実測データから解明した記録。

## 最終的な計算式

```
ユニットスコア = 総合力 × (1 + スコアボーナス%) × 2.037
```

### 総合力

```
総合力 = メンバーパラメータ
       + 衣装スキル
       + パッシブスキル
       + メモリー効果
       + メンバー強化ボーナス
```

| 項目 | 計算方法 |
|---|---|
| メンバーパラメータ | 5人の (パフォ + テク + センス) 合計 |
| 衣装スキル | メンバーパラ × 衣装バフ率 (※) |
| パッシブスキル | サポートスキルのステータスバフ合計 |
| メモリー効果 | ゲーム内定数（ソルバーでは baseline に吸収）|
| メンバー強化ボーナス | Lv 依存の微小値（同上）|

※ 衣装バフは**ステごとに適用**される。「全パラ50%UP」は全ステに50%、「パフォーマンス135%UP」はパフォのみに135%。

### スコアボーナス

```
スコアボーナス = アクティブスキル%
             + 衣装SS%
             + パッシブSB%
             + スペシャルスキル%
```

| 項目 | 計算式 (v2) | 備考 |
|---|---|---|
| アクティブスキル | `52.89 + E[max(score_up × uptime)] / 12.82` | Expected Maximum + 発動率 + SP発動率UP |
| 衣装SS | `衣装スコアサポート% × 0.68` | |
| パッシブSB | `サポートSS合計% × 0.20` | |
| スペシャルスキル | `Σ(SS効果% × 効果秒数) / 曲長` | デフォルト192秒、曲選択で可変 |

v2 Active詳細:
```
uptime = min(1, duration / interval × boosted_prob)
boosted_prob = base_prob × (1 + rate_up_avg)        ← v3で乗算に修正
rate_up_avg  = Σ(SP発動率UP/100 × SP継続 / 曲長)
E[max] = Σ(score_up_i × uptime_i × Π(j<i: 1 - uptime_j))  ※value降順
```

### 定数 2.037

ユニットスコアと `総合力 × (1 + SB%)` の間の定数。5つの異なるチーム構成で検証し、誤差 0.001% 以内で安定。ゲーム内部の基礎倍率と考えられる。

## 解明過程

### Phase 1: 初期モデル（不正確）

当初は以下のモデルを仮定していた:

```
推定スコア = パラメータ合計 × (1 + SS%) × (1 + センタースキル期待値%)
```

SS をパラメータに対する単純な乗算として扱い、センタースキル期待値を `score_up% × duration/interval × probability` で計算。

**問題点**: こよりリーダー（全パラ30% + SS25%）がマリンリーダー（全パラ50%）より強いと予測したが、ゲーム実測では逆だった。

### Phase 2: SS は別系統（バンドリ式の発見）

ホロドリはバンドリ！ガールズバンドパーティと同じ開発会社・同一エンジンであることから、バンドリの確立されたスコア計算式を調査。

バンドリの計算式:
```
1ノーツのスコア = Band Power × 3 × 難易度係数 / ノーツ数 × 判定倍率 × コンボ倍率
```

**重要な発見**: スコアは Band Power（総合力）に対して**線形**。2乗でも2.3乗でもない。

### Phase 3: ゲーム内詳細画面の発見

ゲーム内の「ユニットスコア詳細」画面のスクリーンショットから、総合力とスコアボーナスが**完全に分離された2つの系統**であることが判明。

同じ5人でリーダーだけ変えた比較:

| | マリンリーダー | こよりリーダー |
|---|---|---|
| 総合力 | 156,040 | 136,900 |
| スコアボーナス | 113.4% | 130.2% |
| ユニットスコア | 678,413 | 642,056 |

これにより:
- **衣装のパラバフ** → 総合力に影響
- **衣装のSS** → スコアボーナスに影響
- **スコアボーナスは衣装を変えても同じ**（同じ5人なら）

### Phase 4: 各項目の計算式特定

#### アクティブスキル%

2チーム（ねね入り vs トワ入り）の比較から:
- ねね(score_up=60, dur=9, interval=26) → トワ(score_up=95, dur=8, interval=19) に入替
- ゲーム: 67.1% → 68.6% (差 +1.5%)
- モデル差: Σ(su×d/iv) 変動 = 19.23
- 逆算: k = 19.23 / 1.5 = **12.82**, base = **52.89**

0凸カードのみのチームで**誤差ゼロ**を確認。

注: アクティブスキルの `score_up` は**タイプ条件成立時は conditional 値を使用**するが、**ライフ/コンボ条件は基本値を使用**する。

#### 衣装SS vs パッシブSB

SS変換率が衣装とサポートで大きく異なることが判明:

| SS源 | 額面 | ゲーム表示 | 変換率 |
|---|---|---|---|
| 衣装SS（こより 25%）| 25% | 17.0% | **0.68** |
| サポートSS（合計 35%）| 35% | 7.2% | **0.20** |
| サポートSS（合計 24%）| 24% | 4.7% | **0.20** |
| サポートSS（合計 11%）| 11% | 2.2% | **0.20** |

サポートSSの変換率 0.20 は3データ点で安定（19.6〜20.6%）。

#### スペシャルスキル%

各メンバーのスペシャルスキル（スコアサポート効果% × 効果秒数）を基準曲長で割る:

```
スペシャル% = Σ(SS効果% × 秒数) / 192
```

基準曲長 **192秒** は実測から逆算。ゲーム表示 39.1% に対し計算値 39.2% で一致。

### Phase 5: 2点キャリブレーション

ゲーム内ステータスはレベル・特訓・ボード育成で変動するため、データベース上の値（Lv上限）と乖離する。同じ5人でリーダーを変えた2つのユニットスコアから `stat_scale` と `baseline` を連立方程式で算出:

```
game_score_1 = (raw_params × stat_scale × (1 + costume_rate_1) + support × stat_scale + baseline) × (1 + SB_1%) × 2.037
game_score_2 = (raw_params × stat_scale × (1 + costume_rate_2) + support × stat_scale + baseline) × (1 + SB_2%) × 2.037
```

実測検証:
- マリンL: 678,415 (実測 678,413, 誤差 +2)
- こよりL: 642,058 (実測 642,056, 誤差 +2)

## 重要な発見

### パフォ135%UP > 全パラ50%UP

直感に反するが、パフォーマンスがチーム総ステの37%以上を占める編成では、パフォ135%UPの方が全パラ50%UPより衣装寄与が大きい。

```
パフォ比率42%のチーム:
  パフォ135%: 42% × 135% = 56.7% 相当
  全パラ50%: 50%
  → パフォ135%が6.7%上回る
```

ゲーム内実測でも確認: 水着ノエルL (463,106) > 莉々華L (440,407)。

攻略サイトでは「全パラ50%が最強」とされているが、パフォ特化編成ではこの定説が覆る。

### SS効果は限定的

スコアボーナス全体に占めるSSの割合は小さい:
- アクティブスキル: **67.1%**（支配的）
- スペシャルスキル: **39.1%**
- 衣装SS: 0〜17%
- パッシブSB: 2〜7%

SS を最大化するより、アクティブスキルとスペシャルスキルが高いメンバーを選ぶ方がスコアへの影響が大きい。

### 衣装はスコアボーナスに影響しない

同じ5人でリーダーの衣装を50%UP → 15%UPに変えても、スコアボーナス（アクティブ/パッシブSB/スペシャル）は全て同一値。衣装は総合力にのみ影響する。

## 既知の制約

### 凸（開花）の影響

- データベースは HolodoriDB の 0凸 max level 値
- 1凸: アクティブスキル強化 → アクティブ% に影響
- 3凸: スペシャルスキル強化 → スペシャル% に影響
- 凸カード（おかゆ5凸等）が含まれるチームでは約2%の誤差

### スペシャルスキルの発動率UP

スペシャルスキルに付随する「スキル発動率UP」の寄与は未解明。発動率UPありのチームは予測よりスペシャル%が高く、なしのチームは低い傾向があるが、単純な線形モデルでは矛盾が生じるため保留中。

### アクティブスキルの base 定数 52.89

この定数はスキル発動率UP効果を含んでいる可能性がある。0凸かつ発動率UP持ちカードが含まれるチームでは正確だが、発動率UP持ちの有無でチーム間に差が出る場合、約2%の誤差が生じる。

### 基準曲長 192秒

スペシャルスキル%の計算に使用する192秒は実測から推定した値。曲によって長さが異なる場合、スペシャル%の値がゲーム表示と若干ずれる可能性がある。

v2では曲セレクターで個別の曲の長さ（`playingSeconds`）を使用可能。

## v2 改善事項

### データソース移行

HolodoriDB（`HolodoriDB/holodori-db-jpn-diff`）から `scripts/sync_holodori.py` で自動生成（0〜4凸、任意レベル対応）。
初期は appmedia 攻略サイトから手入力していたが、HolodoriDB への移行により全カード自動生成に切り替え済み。

### ゲーム公式係数 K=2.3 について

HolodoriDB `Setting.json` の `liveDeckEvaluationCoefficientPermilMultiply = 2300` により、
ゲーム公式のデッキ評価係数は **2.3** であることが判明した。

HoloSolveの経験定数 `UNIT_SCORE_K = 2.037` はこの2.3に加えて、曲別スコア係数
（`liveScoreCoefficientPermil` = 2〜9）、コンボボーナス（最大+10%）、ノート種別係数
（フリック1.05x等）を一つの係数に圧縮した近似値である。

K=2.3へ単純置換するとこれらの未モデル化要因を別途補う必要があるため、
現時点では経験式 K=2.037 を維持する。キャリブレーション（stat_scale + baseline）
により個々のユーザー環境で吸収される。

### アクティブスキル: Expected Maximum + 発動率

v2ではExpected Maximumモデルを採用。各ノートで最強のActive 1つだけがスコアに貢献する。

```
uptime_i = min(1, duration_i / interval_i × boosted_prob_i)
boosted_prob_i = base_prob_i × (1 + rate_up_avg)      ← v3で乗算に修正
rate_up_avg   = Σ(SP発動率UP/100 × SP継続 / 曲長)
E[max] = Σ(score_up_i × uptime_i × Π(j<i: 1 - uptime_j))  ※value降順ソート
active_pct = 52.89 + E[max] / 12.82
```

v1ではΣ線形和で全員のActiveを合算し、発動率も無視していた。

### v3: Timeline Expected Score Engine

v3では曲ごとのチャートデータを用いた精密なライブ期待スコア計算を追加。
Unit Score Predictor（v2）は高速全探索用にそのまま維持し、Top候補のみを
Timeline Engineで再評価する二段階方式。

```
全候補 → Legacy Fast Solver → Top 200 → 5!=120順列 Timeline → Final Top N
```

Timeline Engineでは:
- Active発動確率を各trigger時刻で個別に計算（SP Rate Upの時間依存性を反映）
- E[max(active)]を各ノート/ビン時刻で解析的に計算（Monte Carlo不要）
- Score Support × Active Score Up の乗算的相互作用を直接評価
- SP固定5地点に基づく編成順最適化

LiveScoreIndex = TotalPower × Σ(noteWeight × comboMultiplier × skillMultiplier)
- ランキング用相対指標（同一曲内での編成比較に使用）
- ゲーム内絶対スコアとは直接比較不可

未実装項目（フォローアップ）:
- SkillRateCondition（life_1000, combo条件付きSP Rate Up）
- PlayAssumption（AP/FC前提の条件分岐）
- ConditionalScoreUp（Timeline側でのタイプ条件Active）
